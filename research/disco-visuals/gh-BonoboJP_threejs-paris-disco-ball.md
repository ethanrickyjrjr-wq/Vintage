# Three.js Conf Paris 2026 - the Afterparty disco ball
[](https://github.com/BonoboJP/threejs-paris-disco-ball#threejs-conf-paris-2026---the-afterparty-disco-ball)
The mirror ball that hangs on the [threejs.paris schedule](https://threejs.paris/schedule/day2) (scroll to the **Afterparty**), extracted into a repo of its own so anyone at the conference can make it better.
**Improve the effect, open a PR, and if it's merged it ships on the conference site.**
Live demo: **<https://bonobojp.github.io/threejs-paris-disco-ball/>** (rebuilt from `main` on every push)
[![the disco ball](https://github.com/BonoboJP/threejs-paris-disco-ball/raw/main/docs/disco-ball.png)](https://github.com/BonoboJP/threejs-paris-disco-ball/blob/main/docs/disco-ball.png)
## Run it
[](https://github.com/BonoboJP/threejs-paris-disco-ball#run-it)

```
npm install
npm run dev
```

Open the printed URL. WebGPU browsers (Chrome, Edge, Safari 26+) get the WebGPU backend, everything else falls back to WebGL2 automatically - the effect has to look right on both.
Drag to orbit. The panel top-right exposes the same live knobs as the site's tweaks panel (`Afterparty Lights` folder), plus a `Stage` folder for `focus` (0 = far away in the coil, 1 = centred), `fade` (fog) and the sky dim.
## What is where
[](https://github.com/BonoboJP/threejs-paris-disco-ball#what-is-where)  
| file  | what  |  
| --- | --- |  
| `src/DiscoLights.js`  |  **The effect.** Mirror ball material + light shafts + mirror-dot field + backdrop + halo + cable. This is the file the site imports, verbatim. Edit this one.  |  
| `src/main.js`  | The stage: renderer, camera at the site's distance, tinted `RoomEnvironment`, sky gradient, the "AFTERPARTY" ring, GUI. Not shipped to the site - only touch it if the effect genuinely needs a new stage input.  |  
| `src/tintSceneGradient.js`  | Helper copied from the site so the environment reflections match.  |  
`DiscoLights.js` is a self-contained rig written in [TSL](https://github.com/mrdoob/three.js/wiki/Three.js-Shading-Language) on top of `three/webgpu`. It only imports from `three/tsl` and `three/webgpu`, and it must stay that way (see the contract below).
### How the rig is built
[](https://github.com/BonoboJP/threejs-paris-disco-ball#how-the-rig-is-built)
Read the big comment at the top of `src/DiscoLights.js` first - it explains the three ideas the look rests on (gradient LUTs instead of flat tints, the ball being the _source_ of the light, one shared projection frame). In short:
  * `_buildSphere` - the mirror ball: an analytical facet normal per UV tile, per-tile tilt jitter (the twinkle), lamp glints, white pops, rim.
  * `_buildShafts` - one instanced mesh of open-ended tapered tubes rooted _inside_ the sphere.
  * `_buildDots` - one instanced mesh of camera-facing motes emitted from the ball, a third of them cast onto the backdrop.
  * `_buildBackdrop` - the dark bowl behind everything (additive light needs a dark room).
  * `_buildHalo` / `_buildCable` - glow behind the ball, the wire it hangs from.
  * `update( spin, fade, focus, renderOrder, reducedMotion, gains )` - called every frame by the site with the ball's spin phase, fog opacity, proximity to the centre of the schedule coil, its render order, the OS reduced-motion flag and the live tweak gains.


## The contract (what a PR must keep)
[](https://github.com/BonoboJP/threejs-paris-disco-ball#the-contract-what-a-pr-must-keep)
The site constructs and drives the rig like this, and that is all it knows about it:

```
const disco = new DiscoLights( sphereGeometry )   // shared unit SphereGeometry( 1, 48, 24 )
parent.add( disco.root )
disco.update( spin, fade, focus, renderOrder, reducedMotion, gains )  // every frame
disco.reset()   // prop recycled onto another schedule item
disco.hide()
disco.dispose()
```

So a mergeable PR:
  1. Keeps that API (you can add optional keys to `gains` - add them to the panel in `main.js` too and say so in the PR, the site's tweaks panel will get them).
  2. Imports only from `three/tsl` and `three/webgpu`. No new dependencies, no assets to load (bake textures on a canvas at construction like the LUT does).
  3. Renders on **both** backends. Test the WebGL fallback: in DevTools run `Object.defineProperty(navigator, 'gpu', { get: () => undefined })` before load, or use Firefox.
  4. Stays cheap. The ball is one of ~30 items in a scrolling coil on a page that already runs a lot; the rig is a handful of draw calls (everything instanced) and it should stay that way. Nothing per-frame on the CPU beyond a few uniforms.
  5. Honours `reducedMotion` (a constant `spin` must produce a still, correctly composed pose) and `fade` (everything must disappear as the ball recedes into the fog).
  6. Looks good at the site's framing: camera ~4.6 ball radii away, 55deg FOV, ball ~40% of the viewport height at `focus = 1`. That is the default view of `npm run dev`.


## Contributing
[](https://github.com/BonoboJP/threejs-paris-disco-ball#contributing)
  1. Fork this repo, `npm install`, `npm run dev`.
  2. Edit `src/DiscoLights.js`. Keep the comment style - the file explains _why_ every number is what it is, and that is what lets the next person change it.
  3. Before/after screenshot or a short capture in the PR (both backends if you touched shader code).
  4. Open the PR against `main`. See [CONTRIBUTING.md](https://github.com/BonoboJP/threejs-paris-disco-ball/blob/main/CONTRIBUTING.md) for the template.


Ideas that would be welcome: better facet sparkle, a smarter beam gate (a real ball throws a lobe of beams from the facets facing a lamp), a proper volumetric look for the shafts, a floor pool of light, chromatic dispersion on the glints, an audio-reactive `gains.beat`... or something none of us thought of.
## How merged PRs reach the site
[](https://github.com/BonoboJP/threejs-paris-disco-ball#how-merged-prs-reach-the-site)
`src/DiscoLights.js` here and `src/3d/balls/spiral/DiscoLights.js` on the site are the same file. After a merge, the site pulls the new version with

```
pnpm syncDiscoBall
```

which downloads this repo's `main` copy over the site's, prints the diff, and leaves it to be committed. New `gains` keys are added to the site's `partyParams` tweaks by hand.
