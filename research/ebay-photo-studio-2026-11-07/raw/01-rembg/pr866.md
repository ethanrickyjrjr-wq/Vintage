## Summary

Security hardening of `rembg s` and of model loading, plus dependency floors past known advisories.

### HTTP server (`rembg s`)

-   **Cloud models are opt-in.** `atlascloud` and `withoutbg` fall back to the API key in the server's environment, so any caller reaching the port could spend it. They are now only served with `--allow-remote-models` (API and Gradio UI).
-   **Bounded session cache.** Every distinct `extras` built a new model that was never freed, so varying it exhausted memory. Sessions now live in an LRU (`--max-sessions`, default 8), and per-call extras (`sam_prompt`, `cc`, ...) no longer create sessions.
-   **`extras` allowlist.** Only known keys are accepted; `providers`, `sess_opts` and anything else get a 400. Malformed JSON is a 400 instead of being ignored.
-   **Upload size limit.** POST bodies to `/api/remove` are capped at the same 50 MB as `url=` fetches, enforced while streaming (Content-Length and chunked). Oversized requests get a 413.
-   Model name regex is anchored, malformed `bgc` is a 400 instead of a 500, and `ae` is capped at 255.

### Sessions

-   `atlascloud` refuses non-https output URLs (urllib would also open `file://`).
-   `validate_model_path` resolves symlinks, so a link inside the models directory cannot point outside it.

### Dependencies

-   `python-multipart >=0.0.31`, `starlette >=1.3.1` (now an explicit `cli` dependency), `fastapi <1.0.0`, `aiohttp ^3.14.4`, `gradio ^6.16.0`, `black ^26.10.1`. The caret ranges on 0.x versions never let users pick up fixes.
-   `pillow >=12.3.0,<14.0.0`. Most Pillow decoder fixes are only in 13.x, but every gradio release still requires `pillow <13`, so installs with the `cli` extra stay on 12.3 until gradio lifts that cap.

## Behaviour changes

-   Using `atlascloud`/`withoutbg` through the server needs `--allow-remote-models`.
-   Unknown `extras` keys are rejected with 400.

## Testing

-   New `tests/test_server_hardening.py` (24 tests) plus tests in `test_atlascloud.py` and `test_model_home.py`; the server tests fail on `main`.
-   Ran the server, SSRF, session and decontaminate tests in a clean venv with the new dependency set (starlette 1.10, fastapi 0.162, gradio 6.31): 91 passed.
-   Started `rembg s` with the UI under uvicorn: UI and docs return 200, a 60 MB upload returns 413 (with and without chunked encoding), a private-address `url=` returns 400.
-   `test_remove.py` (downloads models) was not run locally.

Several pins kept installs on releases with published advisories, and the
caret ranges on 0.x versions (\`^0.0.21\`, \`^0.128.0\`) never let users pick up
the fixes:

- python-multipart >=0.0.31 (parses every upload; CPU DoS fixes)
- starlette >=1.3.1, now an explicit cli dependency since it parses every
  request and fastapi no longer bounds it
- fastapi widened to <1.0.0
- aiohttp ^3.14.4 (fetches the url= images)
- gradio ^6.16.0
- black ^26.10.1 (dev)

pillow is widened to >=12.3.0,<14.0.0. Most of its decoder fixes are only
in 13.x, but every gradio release still requires pillow <13, so installs
with the cli extra stay on 12.3 until gradio lifts that cap.

about.
