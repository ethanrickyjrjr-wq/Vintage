## The problem
On a soft edge, a pixel is not purely foreground or purely background — the camera captured a blend:

```
captured = alpha * foreground + (1 - alpha) * background

```

Making that pixel semi-transparent does not undo the blend, so the background color survives as a colored halo around hair and fine detail. A subject shot against grass keeps a green rim.
## Why alpha matting wasn't the answer
`alpha_matting_cutout` already fixed this, but only as a side effect of a two-step process:

```
alpha = estimate_alpha_cf(img_normalized, trimap_normalized)   # re-derives alpha from a trimap
foreground = estimate_foreground_ml(img_normalized, alpha)     # <- this is the color fix
```

The two were welded together. To get the cheap second step you had to pay for the expensive first one — which also throws away the soft alpha that BiRefNet and friends already produce, re-deriving it from a coarse threshold-based trimap. Users who only wanted the halo gone were paying for a mask refinement they didn't need.
## The change
`decontaminate_cutout` keeps the model's alpha and runs only the foreground estimation. It reuses `estimate_foreground_ml` and `stack_images`, both already imported for alpha matting — **no new dependency** , and the cost is negligible next to inference.
The three modes are alternatives, not layers (`-a` already decontaminates internally, so the branches are mutually exclusive):  
| Mode  | Flag  | Fixes edge color  | Refines the mask  |  
| --- | --- | --- | --- |  
| Naive  | _(default)_  | No  | No  |  
| Decontaminate  | `-dc`  | Yes  | No  |  
| Alpha matting  | `-a`  | Yes  | Yes  |  
## Behavior change worth reviewing
Beyond the opt-in flag, this changes the **alpha matting fallback**. When that solver fails to converge (it does, on real images), the old code fell back to `naive_cutout`. It now falls back to `decontaminate_cutout` — a caller who asked for `-a` clearly wanted clean edges, so returning fringed output serves them poorly. This affects users who pass `-a` and hit a solver failure.
## Surface
  * `remove(..., decontaminate=False)` — off by default
  * `-dc` / `--decontaminate` on `i` and `p`
  * `dc` query + form param on the HTTP server, and a Gradio checkbox
  * `decontaminate_cutout()` exported from `rembg.bg`


## Testing
New `tests/test_decontaminate.py` builds a synthetic hair-on-green-screen fixture, so the true foreground color is known exactly and the correction can be measured rather than eyeballed. Three tests: color is recovered, alpha is untouched, opaque pixels are left alone. No model download, runs in ~1s.
Verified end to end: the full suite passes against the **unchanged** result fixtures (default output is byte-identical to `2.0.x`), and the flag was exercised through the library, both CLI commands, and the HTTP API.
## Docs
README gains a "Choosing an edge mode" section covering when to use each of the three, which models pair well with which, and why `-ppm` and `-dc` don't mix (post-processing thresholds the mask to fully binary, leaving nothing to correct).
## Note on naming
"Despill" was the term in the issue, but in Photoshop/Nuke that means chroma-key spill suppression — a different operation. This is what Photoshop calls _Decontaminate Colors_ and Nuke calls _decontamination_ , hence the name.
