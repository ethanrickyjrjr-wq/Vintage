## Weights
The four checkpoints are attached to the `v0.0.0` release. Verified by downloading each from the release URL into a clean `REMBG_HOME` and letting pooch enforce the checksum:  
| Release asset  | sha256  | Size  |  
| --- | --- | --- |  
| `vitmatte-small-distinctions-646.onnx`  | `d232841a…83631`  | 110 MB  |  
| `vitmatte-small-composition-1k.onnx`  | `659b9bb2…373a24`  | 110 MB  |  
| `vitmatte-base-distinctions-646.onnx`  | `d3019083…cc8c1`  | 380 MB  |  
| `vitmatte-base-composition-1k.onnx`  | `87bb1097…ec1f2`  | 380 MB  |  
## What
A fourth edge mode, `-vm`, that refines the mask with [ViTMatte](https://github.com/hustvl/ViTMatte) instead of pymatting's closed-form solver.
  * `rembg/matting.py` — new module: trimap construction, variant registry, ONNX inference
  * `rembg/bg.py` — `vitmatte` / `vitmatte_model` params on `remove()`
  * `rembg/commands/{i,b,p}_command.py` — `-vm` flag
  * `rembg/commands/s_command.py` — query param, form param, Gradio checkbox
  * `tests/test_matting.py` — 11 tests covering trimap invariants and variant resolution


## Why
`-a` is the only mode that re-estimates coverage, but its solver clips the fine tips of hair and can fail to converge. ViTMatte predicts the alpha directly, recovering more of exactly the detail `-a` is invoked for, and a forward pass cannot fail.
Measured on two portraits, all starting from the same `bria-rmbg` mask (`contam` = mean luminance in the semi-transparent band; lower means less background bled into the hair):  
| mode  | soft px  | contam ↓  | time  |  
| --- | --- | --- | --- |  
| naive  | 53199  | 87.2  | 0.00s  |  
| `-dc`  | 53199  | **49.2**  | 0.09s  |  
| `-a`  | 56981  | 53.1  | 0.59s  |  
| **`-vm`** | **66630**  | 51.3  | 2.1s  |  
The gain is coverage: ~17% more soft pixels than `-a`, at comparable contamination.
## Checkpoint choice
`-x '{"vitmatte_model": "base-distinctions-646"}'` selects any of the four. Default is `small-distinctions-646`, which is **not** the one the paper's benchmarks rank highest — measured on real photos the training set mattered more than model size:  
| checkpoint  | size  | soft px  | contam ↓  | time  |  
| --- | --- | --- | --- | --- |  
| small-composition-1k  | 110 MB  | 66630  | 51.3  | 2.6s  |  
| base-composition-1k  | 380 MB  | 66856  | 50.8  | 5.9s  |  
| **small-distinctions-646**  | **110 MB**  | 67789  | **45.3**  | **2.1s**  |  
| base-distinctions-646  | 380 MB  | 71498  | 45.2  | 5.3s  |  
Distinctions-646 beats Composition-1k by ~6 contamination points at identical size and speed; going small→base costs 3.5× the download and 2.5× the runtime for ~0.1.
## Design notes
**No torch.** ViTMatte is MIT and exports to plain ONNX, so this runs on the onnxruntime stack rembg already has. No second inference path, no ~2 GB dependency.
**Fixed 1024×1024, deliberately.** VitDet builds its relative position tables from the input dimensions, so an export with dynamic H/W returns _silently wrong_ alphas at other sizes (measured error 0.23–0.56 on a 0–1 alpha; larger sizes crash on `GatherND`). Fixed resolution matches how every existing session already works.
**Paired with decontamination.** ViTMatte predicts coverage but not colour, so its alpha goes through the same `estimate_foreground_ml` that `-dc` uses. Skipping that leaves the recovered strands carrying the old background colour — measured at naive-level contamination (119.6 vs 67.4).
## Testing
  * Full suite: 49 passed.
  * black / isort / flake8 / bandit clean. (mypy crashes with `Cannot serialize TypeGuardedType` on my machine — reproduces on a clean `main`, so it is environment-specific, not from this branch.)
  * Verified end-to-end against locally staged weights: `remove()` default → 55215 soft px, `-vm` → 69371, `-vm` + base → 72990; unknown variant raises a `ValueError` listing the valid names; CLI `-vm -x '{"vitmatte_model": "base-distinctions-646"}'` writes a valid PNG.


## Not included
`b_command` has no `-dc` flag (pre-existing gap); I added `-vm` there but did not backfill `-dc`, to keep this diff scoped.
