# whitebg — Batch White-Background Converter

[](#whitebg--batch-white-background-converter)

**English** | [简体中文](/jimmyXiang123/whitebg/blob/main/README.zh-CN.md)

Turn batches of e-commerce product photos into **clean white-background main images**, fully offline. `rembg` handles the cutout; this tool adds the delivery-grade post-processing that marketplaces actually require — subject cropping, consistent padding, square canvas, exact pixel size, soft shadow, and edge decontamination. Ships with both a desktop GUI and a CLI.

> Everything runs locally. No uploads, no network calls (except the one-time model download).

```
original (any background)  ──▶  cutout  ──▶  crop to subject + padding  ──▶  square / size  ──▶  white or transparent  ──▶  1200×1200 JPG
```

## Features

[](#features)

-   **Batch processing** — drop in a whole folder; recursive scan, skip already-processed files, optional multiprocessing
-   **Two entry points** — Tkinter GUI (drag-and-drop, thumbnail preview, progress bar) or CLI (scriptable, schedulable)
-   **Delivery-grade post-processing** — auto crop to subject, uniform padding ratio, square canvas, exact `N×N` pixels, optional soft shadow
-   **Edge decontamination** — recovers the foreground colour from alpha, removing background colour bleeding (coloured fringes / halos) on soft edges
-   **EXIF orientation fix** — portrait phone shots no longer come out sideways
-   **Three models to choose from** — `u2net` (fastest) / `birefnet-general-lite` (balanced, default) / `birefnet-general` (most accurate)
-   **Packages into a portable exe** — includes a Windows 7 compatible build config (see [docs/windows7.md](/jimmyXiang123/whitebg/blob/main/docs/windows7.md))

## What the output looks like

[](#what-the-output-looks-like)

With no arguments you get a standard e-commerce main image: **1200×1200 white JPG**, subject centred, 6% padding on all sides, no shadow. Change the flags for other tastes:

# source .venv/bin/activate     # macOS / Linux (untested)

pip install -r requirements.txt

## Usage

[](#usage)

### GUI

[](#gui)

python -m whitebg

1.  **Drag images or a folder straight into the window**, or click "＋ Add images / Add folder"
2.  Pick an output folder and a model ("Speed first" ≈ 2–6 s/image, "Quality first" ≈ 15–20 s/image)
3.  Click "Start", then "Open output folder" when it finishes

The first launch takes 30–60 s while the model loads (warm-up happens in the background and the progress bar shows "loading model"); every image after that is done in seconds.

### CLI

[](#cli)

# Most common: whole folder → 1200×1200 white JPG
python -m whitebg -i input -o output

# Transparent PNG, keep original aspect ratio
python -m whitebg -i input -o output --transparent --format png --no-square

# High-quality model + shadow, try the first 5 images
python -m whitebg -i input -o output -m birefnet-general --shadow --limit 5

## FAQ

[](#faq)

**Q: The subject looks small inside the 1200×1200 canvas.** By default the tool only shrinks, never enlarges: an original smaller than the canvas is not upscaled (upscaling only blurs it). Add `--upscale`, or start with larger source images.

**Q: There is a coloured fringe / halo around the edges.** The background colour bled into the edges (common with green screens and blue walls). Decontamination is on by default; make sure you have not added `--no-decontaminate`.

**Q: A particular image came out badly (holes / smeared / leftover fragments).** Every model has weak spots. Try `birefnet-general-lite` or `birefnet-general` first — that solves most cases. For hair and fur add `--alpha-matting`.

**Q: `python -m whitebg` does not open a window.** You need a Python build that includes Tk (the official python.org installer bundles it; conda does too). On Linux install `python3-tk` separately.

**Q: The first run hangs on "loading model".** It is downloading weights, or compiling JIT code — this is normal. For offline environments, place the models in `models/` beforehand.

**Q: Why not a single-file exe?** A single-file build unpacks hundreds of MB into a temp folder on every launch — slow on older machines and frequently blocked by antivirus. The one-folder build starts faster, is more stable, and is equally portable.
