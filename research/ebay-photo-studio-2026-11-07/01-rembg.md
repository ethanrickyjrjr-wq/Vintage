6. Issue #668 detail (VERIFIED_FETCHED, https://github.com/danielgatis/rembg/issues/668, still open, labelled bug and stale). Original error: "Failed to load library libonnxruntime_providers_cuda.so with error: libcublasLt.so.12: cannot open shared object file". Working recipes in the thread: a user ran Docker `FROM nvidia/cuda:12.4.1-cudnn-devel-ubuntu22.04` with `pip install onnxruntime-gpu` and `pip install "rembg[gpu,cli]"` (driver 550.120, CUDA 12.4, onnxruntime-gpu 1.20.1 at that time), but it still used CPU only until he forced `providers=['CUDAExecutionProvider']` in rembg/sessions/base.py. Another user advised `new_session("{model_name}", providers=['CUDAExecutionProvider'])` to avoid TensorRT noise, cuDNN 9 (`libcudnn.so.9`) with CUDA 12. Takeaway: on Windows the GPU path needs CUDA 12 runtime DLLs and cuDNN 9 on PATH matching the onnxruntime-gpu build, and TensorRT errors in the log are harmless noise when CUDA provider loads. The easy way to get those DLLs without a system CUDA install is UNVERIFIED (pip nvidia-cudnn-cu12 wheels were suggested in the thread via LD_LIBRARY_PATH on Linux only). Plan: try GPU first, check `onnxruntime.get_available_providers()` and time one image; if it falls back to CPU, CPU is acceptable at this volume.

8. CLI subcommands (VERIFIED_FETCHED, README.md and source). `i` single files; `p` folders (batch); `s` HTTP server; `b` RGB24 pixel binary stream (for FFmpeg); `d` download models ahead of time (`rembg d <model names...>`, source `download_models(models)`; with no names it downloads all, UNVERIFIED but implied by nargs=-1, so always name models); `m` migrate models from legacy `~/.u2net` (`--dry-run`, `--delete-source`, `--clean-orphans`).
9. Flags for `i` and `p` (source i_command.py, p_command.py, main). `-m/--model` default "bria-rmbg" (TRAP confirmed); `-a/--alpha-matting`; `-af` foreground threshold default 240; `-ab` background threshold default 10; `-ae` erode size default 10; `-om/--only-mask`; `-ppm/--post-process-mask`; `-dc/--decontaminate` ("remove the background color fringing left on soft edges"); `-vm/--vitmatte` ("refine the edges with ViTMatte, recovering more fine detail than -a"); `-bgc/--bgcolor` four ints "R G B A", default 0 0 0 0, e.g. `-bgc 255 255 255 255` composites onto opaque white; `-x/--extras` JSON string. `p` only: `-w/--watch` ("watches a folder for changes"), `-d/--delete_input`, `--accept-usage-cost` (only matters for paid cloud models). `s`: `-p/--port` 7000, `-h/--host` default 0.0.0.0, `-l/--log_level`, `-t/--threads`, `--no-ui`, `--allow-remote-models`, `--max-sessions` 8; API docs at `http://localhost:7000/api`; query params include model, a, om, ppm, dc, vm, bgc, extras. The issue-109 owner answer: output "is a transparent background, but you can use a third-party library to modify the image after background removal" (older, but `-bgc` now exists in source).
10. Behaviour details that matter for a pipeline (VERIFIED_FETCHED, p_command.py). `p` writes `<output>/<input name with .png suffix>`; it SKIPS any file whose output already exists (so re-running with a new model into the same folder does nothing); it globs `**/*` recursively but the watch observer is non-recursive; typing a file named `stop.txt` into the watched folder stops watch mode; `-w` first processes everything already there, then watches. The model session is created once per command, so use `p` or the Python `new_session` for batches, not a loop of `i`.
11. Edge-mode guidance quoted from README (https://raw.githubusercontent.com/danielgatis/rembg/main/README.md): "Use the default (naive) when the subject has hard edges — products, cars, logos, screenshots". "Use `-dc` when the cutout has a colored halo ... it is cheap enough to leave on for a whole batch." "Use `-a` when the shape of the mask is wrong ... much slower than `-dc`. That solver can fail to converge." "Use `-vm` ... costs an extra ~110 MB download". "If you are batch-processing and cannot inspect each result, prefer `-dc` over `-a`: it is faster and cannot fail." "`-ppm` ... thresholds the mask into a fully binary one, which leaves no partially transparent pixels ... Combining it with `-dc` is pointless." "The newer models (`bria-rmbg`, `birefnet-*`, `isnet-general-use`) already produce a soft, well-shaped alpha, so their masks rarely need `-a`." For lace, fringe and fur on clothes, the README's own path is `-dc` first, then `-vm`; `-a` is the older route. Do NOT combine `-dc` with `-a` or `-ppm` (redundant).

17. Key risk for this use case (UNVERIFIED reasoning): rembg masks "salient object". A garment on a mannequin is one object plus the mannequin; any general model will keep the mannequin. For "clothes on mannequin, white background" this is what we want (the mannequin stays); the "ghost mannequin" look, where the mannequin disappears, is a different job rembg does not do. The two real risks are mannequin stands, hanging wires and semi-transparent fabric (lace, tulle, chiffon) where the mask holes in or turns white. A quick fix is a two-pass test: `-m birefnet-general -dc` and `-m birefnet-general -vm`, compared on the example photos Ricky sends.

## Recommendations for Ricky and the build

1. Keep pin `rembg[cpu,cli]` or `rembg[gpu,cli]` at 2.0.87 (or 2.0.86; either), Python 3.12 venv, and always pass `-m`. Suggested command for the main run: `rembg p -m birefnet-general -dc -bgc 255 255 255 255 INBOX OUTBOX`. Because `p` skips existing outputs, use a fresh output folder per model trial.
