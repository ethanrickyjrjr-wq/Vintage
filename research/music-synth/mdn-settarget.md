# AudioParam: setTargetAtTime() method
Baseline 
Widely available
This feature is well established and works across many devices and browser versions. It’s been available across browsers since July 2015.
  * [ See full compatibility ](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam/setTargetAtTime#browser_compatibility)
  * [ Learn more ](https://developer.mozilla.org/en-US/docs/Glossary/Baseline/Compatibility)


The `setTargetAtTime()` method of the [`AudioParam`](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam) interface schedules the start of a gradual change to the `AudioParam` value. This is useful for decay or release portions of ADSR envelopes.
## In this article
  * [Syntax](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam/setTargetAtTime#syntax)
  * [Description](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam/setTargetAtTime#description)
  * [Examples](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam/setTargetAtTime#examples)
  * [Specifications](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam/setTargetAtTime#specifications)
  * [Browser compatibility](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam/setTargetAtTime#browser_compatibility)
  * [See also](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam/setTargetAtTime#see_also)


##  [Syntax](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam/setTargetAtTime#syntax)
###  [Parameters](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam/setTargetAtTime#parameters) 

[`target`](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam/setTargetAtTime#target)
    
The value the parameter will start to transition towards at the given start time. 

[`startTime`](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam/setTargetAtTime#starttime)
    
The time that the exponential transition will begin, in the same time coordinate system as [`AudioContext.currentTime`](https://developer.mozilla.org/en-US/docs/Web/API/BaseAudioContext/currentTime "AudioContext.currentTime"). If it is less than or equal to `AudioContext.currentTime`, the parameter will start changing immediately. 

[`timeConstant`](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam/setTargetAtTime#timeconstant)
    
The time-constant value, given in seconds, of an exponential approach to the target value. The larger this value is, the slower the transition will be.
###  [Return value](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam/setTargetAtTime#return_value)
A reference to this `AudioParam` object. Some older browser implementations of this interface return [`undefined`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/undefined).
##  [Description](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam/setTargetAtTime#description)
The change starts at the time specified in `startTime` and exponentially moves towards the value given by the `target` parameter. The decay rate as defined by the `timeConstant` parameter is exponential; therefore the value will never reach `target` completely, but after each timestep of length `timeConstant`, the value will have approached `target` by another 1-e-1≈63.2%1 - e^{-1} \approx 63.2%. For the complete formula (which uses a first-order linear continuous time-invariant system), check the [Web Audio specification](https://webaudio.github.io/web-audio-api/#dom-audioparam-settargetattime "External link \(opens in new tab\)").
If you absolutely need to reach the target value by a specific time, you can use [`AudioParam.exponentialRampToValueAtTime()`](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam/exponentialRampToValueAtTime). However, for mathematical reasons, that method does not work if the current value or the target value is `0`.
###  [Choosing a good `timeConstant`](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam/setTargetAtTime#choosing_a_good_timeconstant)
As mentioned above, the value changes exponentially, with each `timeConstant` bringing you another 63.2% toward the target value. You don't have to worry about reaching the target value; once you are close enough, any further changes will be imperceptible to a human listener.
Depending on your use case, getting 95% toward the target value may already be enough; in that case, you could set `timeConstant` to one third of the desired duration.
For more details, check the following table on how the value changes from 0% to 100% as the time progresses.  
| Time since `startTime`  | Value  |  
| --- | --- |  
| `0 * timeConstant`  | 0%  |  
| `0.5 * timeConstant`  | 39.3%  |  
| `1 * timeConstant`  | 63.2%  |  
| `2 * timeConstant`  | 86.5%  |  
| `3 * timeConstant`  | 95.0%  |  
| `4 * timeConstant`  | 98.2%  |  
| `5 * timeConstant`  | 99.3%  |  
| `n * timeConstant`  | 1  |  
1-e-n1 - e^{-n}
##  [Examples](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam/setTargetAtTime#examples)
In this example, we have a media source with two control buttons (see the [webaudio-examples repo](https://github.com/mdn/webaudio-examples/blob/main/audio-param/index.html "External link \(opens in new tab\)") for the source code, or [view the example live](https://mdn.github.io/webaudio-examples/audio-param/ "External link \(opens in new tab\)").) When these buttons are pressed, `setTargetAtTime()` is used to fade the gain value up to 1.0, and down to 0, respectively, with the effect starting after 1 second, and the length of time the effect lasts being controlled by the timeConstant.
