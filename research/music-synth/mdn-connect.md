# AudioNode: connect() method
Baseline 
Widely available
This feature is well established and works across many devices and browser versions. It’s been available across browsers since July 2015.
  * [ See full compatibility ](https://developer.mozilla.org/en-US/docs/Web/API/AudioNode/connect#browser_compatibility)
  * [ Learn more ](https://developer.mozilla.org/en-US/docs/Glossary/Baseline/Compatibility)


The `connect()` method of the [`AudioNode`](https://developer.mozilla.org/en-US/docs/Web/API/AudioNode) interface lets you connect one of the node's outputs to a target, which may be either another `AudioNode` (thereby directing the sound data to the specified node) or an [`AudioParam`](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam), so that the node's output data is automatically used to change the value of that parameter over time.
## In this article
  * [Syntax](https://developer.mozilla.org/en-US/docs/Web/API/AudioNode/connect#syntax)
  * [Examples](https://developer.mozilla.org/en-US/docs/Web/API/AudioNode/connect#examples)
  * [Specifications](https://developer.mozilla.org/en-US/docs/Web/API/AudioNode/connect#specifications)
  * [Browser compatibility](https://developer.mozilla.org/en-US/docs/Web/API/AudioNode/connect#browser_compatibility)
  * [See also](https://developer.mozilla.org/en-US/docs/Web/API/AudioNode/connect#see_also)


##  [Syntax](https://developer.mozilla.org/en-US/docs/Web/API/AudioNode/connect#syntax)
###  [Parameters](https://developer.mozilla.org/en-US/docs/Web/API/AudioNode/connect#parameters) 

[`destination`](https://developer.mozilla.org/en-US/docs/Web/API/AudioNode/connect#destination)
    
The [`AudioNode`](https://developer.mozilla.org/en-US/docs/Web/API/AudioNode) or [`AudioParam`](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam) to which to connect. 

[`outputIndex` Optional](https://developer.mozilla.org/en-US/docs/Web/API/AudioNode/connect#outputindex)
    
An index specifying which output of the current `AudioNode` to connect to the destination. The index numbers are defined according to the number of output channels (see [Audio channels](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Basic_concepts_behind_Web_Audio_API#audio_channels)). While you can only connect a given output to a given input once (repeated attempts are ignored), you can connect an output to multiple inputs by calling `connect()` repeatedly. This makes [fan-out](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Basic_concepts_behind_Web_Audio_API#fan-in_and_fan-out) possible. The default value is 0. 

[`inputIndex` Optional](https://developer.mozilla.org/en-US/docs/Web/API/AudioNode/connect#inputindex)
    
An index describing which input of the destination you want to connect the current `AudioNode` to; the default is 0. The index numbers are defined according to the number of input channels (see [Audio channels](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Basic_concepts_behind_Web_Audio_API#audio_channels)). It is possible to connect an `AudioNode` to another `AudioNode`, which in turn connects back to the first `AudioNode`, creating a cycle.
###  [Return value](https://developer.mozilla.org/en-US/docs/Web/API/AudioNode/connect#return_value)
If the destination is a node, `connect()` returns a reference to the destination [`AudioNode`](https://developer.mozilla.org/en-US/docs/Web/API/AudioNode) object, allowing you to chain multiple `connect()` calls. In some browsers, older implementations of this interface return [`undefined`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/undefined).
If the destination is an `AudioParam`, `connect()` returns `undefined`.
###  [Exceptions](https://developer.mozilla.org/en-US/docs/Web/API/AudioNode/connect#exceptions) 

`IndexSizeError` [`DOMException`](https://developer.mozilla.org/en-US/docs/Web/API/DOMException) 
    
Thrown if the value specified as `outputIndex` or `inputIndex` doesn't correspond to an existing input or output. 

`InvalidAccessError` [`DOMException`](https://developer.mozilla.org/en-US/docs/Web/API/DOMException) 
    
Thrown if the destination node is not part of the same audio context as the source node. 

`NotSupportedError` [`DOMException`](https://developer.mozilla.org/en-US/docs/Web/API/DOMException) 
    
Thrown if the specified connection would create a cycle (in which the audio loops back through the same nodes repeatedly) and there are no [`DelayNode`](https://developer.mozilla.org/en-US/docs/Web/API/DelayNode) objects in the cycle to prevent the resulting waveform from getting stuck constructing the same audio frame indefinitely. Also thrown if the `inputIndex` parameter is used while the destination is an [`AudioParam`](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam).
##  [Examples](https://developer.mozilla.org/en-US/docs/Web/API/AudioNode/connect#examples)
###  [Connecting to an audio input](https://developer.mozilla.org/en-US/docs/Web/API/AudioNode/connect#connecting_to_an_audio_input)
The most obvious use of the `connect()` method is to direct the audio output from one node into the audio input of another node for further processing. For example, you might send the audio from a [`MediaElementAudioSourceNode`](https://developer.mozilla.org/en-US/docs/Web/API/MediaElementAudioSourceNode)—that is, the audio from an HTML media element such as [`<audio>`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/audio)—through a band pass filter implemented using a [`BiquadFilterNode`](https://developer.mozilla.org/en-US/docs/Web/API/BiquadFilterNode) to reduce noise before then sending the audio along to the speakers.
This example creates an oscillator, then links it to a gain node, so that the gain node controls the volume of the oscillator node.
###  [AudioParam example](https://developer.mozilla.org/en-US/docs/Web/API/AudioNode/connect#audioparam_example)
In this example, we will be altering the gain value of a [`GainNode`](https://developer.mozilla.org/en-US/docs/Web/API/GainNode) using an [`OscillatorNode`](https://developer.mozilla.org/en-US/docs/Web/API/OscillatorNode) with a slow frequency value. This technique is know as an _LFO_ -controlled parameter.
#### AudioParam notes
It is possible to connect an `AudioNode` output to more than one [`AudioParam`](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam), and more than one AudioNode output to a single [`AudioParam`](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam), with multiple calls to `connect()`. [Fan-in and fan-out](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Basic_concepts_behind_Web_Audio_API#fan-in_and_fan-out) are therefore supported.
An [`AudioParam`](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam) will take the rendered audio data from any `AudioNode` output connected to it and convert it to mono by [down-mixing](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Basic_concepts_behind_Web_Audio_API#up-mixing_and_down-mixing) (if it is not already mono). Next, it will mix it together with any other such outputs, and the intrinsic parameter value (the value the [`AudioParam`](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam) would normally have without any audio connections), including any timeline changes scheduled for the parameter.
Therefore, it is possible to choose the range in which an [`AudioParam`](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam) will change by setting the value of the [`AudioParam`](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam) to the central frequency, and to use a [`GainNode`](https://developer.mozilla.org/en-US/docs/Web/API/GainNode) between the audio source and the [`AudioParam`](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam) to adjust the range of the [`AudioParam`](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam) changes.
